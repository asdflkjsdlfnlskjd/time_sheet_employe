# CHANGELOG - Табель Учета Рабочего Времени

## [v1.1.0] - 2026-04-16

### 🎨 Улучшения UI

#### ✅ Фиксирование Legend Items
- **Проблема**: Блок с условными обозначениями (legend) скроллился вместе с таблицей по горизонтали
- **Решение**: Перемещена легенда вне контейнера горизонтального скролла, применено `position: sticky`
- **Файлы**: 
  - `resources/views/admin/Main/index.blade.php` - реорганизована структура HTML
  - `public/css/main.css` - добавлены стили для `.legend-fixed`
- **Результат**: Легенда теперь остается видима при горизонтальном скролле таблицы
- **z-index**: 10 (над таблицей, под модальными окнами)

**Контроллер MainController::saveTimeRecords()**:
- ✅ Валидация структуры данных (проверка всех обязательных полей)
- ✅ Валидация значений:
  - День: 1-31
  - Месяц: 1-12
  - Год: 2000-2100
  - Часы: 0-24
  - Дата должна быть валидной (checkdate)
- ✅ Валидация статуса (только разрешенные значения)
- ✅ Проверка прав доступа (обычный админ → только свой отдел)
- ✅ Кэширование сотрудников (вместо N+1 запросов)
- ✅ Использование `upsert()` для оптимизации БД
- ✅ Возврат детальной статистики (saved, skipped, access_denied)
- ✅ Логирование всех операций

**HTTP Статусы**:
- 200 ✅ - Успешно
- 401 ❌ - Не авторизован
- 403 ❌ - Нет прав доступа
- 422 ❌ - Ошибка валидации
- 500 ❌ - Внутренняя ошибка

#### Новый API Endpoint

**PATCH /time-records/{employeeId}/{date}**
- 📍 Описание: Обновить или создать одну запись о времени
- 📌 Параметры URL:
  - `employeeId` - ID сотрудника
  - `date` - Дата в формате YYYY-MM-DD
- 📌 Body (JSON):
  ```json
  {
    "status": "present",
    "hours": 8.5
  }
  ```
- ✅ Полная валидация входных данных
- ✅ Проверка прав доступа
- ✅ Возврат объекта созданной/обновленной записи
- ✅ Логирование операций

**Файлы**:
- `app/Http/Controllers/Main/MainController.php` - новый метод `updateTimeRecord()`
- `routes/web.php` - новый маршрут `PATCH /time-records/{employeeId}/{date}`

### 🔄 Миграция и Обновление

**Для обновления существующей установки**:

1. Обновить файлы контроллера:
   ```bash
   cp app/Http/Controllers/Main/MainController.php <backup>
   # Обновить файл
   ```

2. Обновить view:
   ```bash
   cp resources/views/admin/Main/index.blade.php <backup>
   # Обновить файл
   ```

3. Обновить CSS:
   ```bash
   cp public/css/main.css <backup>
   # Обновить файл
   ```

4. Обновить routes:
   ```bash
   cp routes/web.php <backup>
   # Обновить файл
   ```

5. Очистить кэш (если используется):
   ```bash
   php artisan config:clear
   php artisan cache:clear
   ```

**Обратная совместимость**: ✅ Полная
- Все старые вызовы API продолжают работать
- POST /main/save-time-records остается неизменным
- Новый PATCH endpoint не конфликтует с существующим кодом

### 📝 Примеры Использования

#### JavaScript
```javascript
const data = [{
  employee_id: 1,
  day: 15,
  status: 'present',
  hours: 8.5,
  month: 4,
  year: 2026
}];

fetch('/main/save-time-records', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-TOKEN': document.querySelector('meta[name="csrf-token"]').content
  },
  body: JSON.stringify(data)
});
```

#### Единичное обновление
```javascript
fetch('/time-records/1/2026-04-15', {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-TOKEN': token
  },
  body: JSON.stringify({ status: 'present', hours: 8.5 })
});
```
